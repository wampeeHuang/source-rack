# 分类体系对抗性审查发现

**审查日期**: 2026-08-04  
**审阅对象**: `_review/brief.md`；并以 `server.js`、`check.js` 和 594 个源文件为证据。  
**结论**: 方向可行，但不应按当前简报直接实施；须先补齐迁移规格、口径和验收测试。

## 阻断项

### [P0] “不改 594 个源文件”没有定义运行时迁移契约，现有逻辑不会自动完成一级归并

新一级中只有 `AI`、`设计`、`电商`、`媒体`、`产品` 是现有字面标签；`工具/开发`、`媒体/社区`、`产品/商业` 不是。更关键的是，建筑、室内设计、家居生活、景观、开发、前端、工具、社区、写作、学习、参考、搜索等旧一级仍会留在每张卡的 `domains` 数组中。

当前 `autoAssignSecondaries()` 只在原数组上追加标签；UI 筛选也只是判断 `data-domain` 是否包含被点击的字符串。因此，若重写时没有一个统一的“读入后规范化”步骤，`[室内设计, 家居生活]` 这类卡既不会成为新 `设计` 的成员，也不会被二级父子关系识别；筛选结果和二级芯片都会漏卡。修改 `DOMAIN_ORDER` 本身不会迁移任何数据。

必须在代码变更前确定并测试一个纯函数，例如 `normalizeDomains(legacyDomains, title, url) -> { primary, secondary, tags }`，并保证：每个源恰有一个主一级、恰有一个规范二级（或显式允许的“未细分”）、旧标签仅作为兼容别名而不参与主筛选。该函数须同时供页面渲染、自动归类、健康检查和 API 使用。

### [P0] 覆盖源数的统计口径错误，不能作为方案验收基线

简报中的“设计 224”是旧标签出现次数 `126(设计)+29(建筑)+45(室内设计)+21(家居生活)+3(景观)`，不是去重后的源数；实际去重后是 **137** 个源。类似地，工具/开发是 91 次标签出现、但仅 **89** 个唯一源；媒体/社区是 58 次、但仅 **56** 个唯一源。

“产品/商业 28”也无法由当前数据复现：现有 `产品 11 + IP管理 12 + 招聘网站 4 + 电子工厂 3` 合并后是 **30** 个唯一源，且广告等还需要从媒体类迁入。一级表合计 743 亦不可能是 594 个唯一源的分配结果。

验收应同时公布两组数字：`unique_primary_count`（七项之和必须为 594）和 `secondary_assignment_count`（允许大于 594，但不得称为覆盖源数）。在主一级“每源唯一”的设计下，38 个当前跨组源（如 Figma、Product Hunt、小红书）必须有明确的主归属和可选的交叉标签规则。

### [P0] 受影响的分类定义不止简报列出的 `server.js` 六处，遗漏 `check.js` 会使发布后自检失败

当前一级列表至少分散在：页面脚本中的 `TOP_DOMAINS`、服务端 `TOP_DOMAINS`、渲染处 `DOMAIN_ORDER`、以及 `check.js` 的 `DOMAIN_ORDER`。`check.js` 目前用它断言“每源至少一个一级领域”；改成 7 项而不接入同一规范化函数时，会把仍带旧一级的源判为缺一级。

现状也已不一致：渲染 `DOMAIN_ORDER` 有 17 项，两个 `TOP_DOMAINS` 均只有 13 项，而 `CLAUDE.md` 列出 14 项。应把分类词表和别名映射收敛为一个可导入的常量/模块，并以迁移前后同一数据集的测试锁定它，不能继续手工同步多份数组。

## 高风险设计问题

### [P1] 二级不是 MECE：分类维度混用“内容主题、资产形态、产品能力、用户用途”

“设计灵感/设计素材/设计工具”是用途或供给形态，“室内与建筑/UI/UX/品牌与平面/动效”是内容主题。一个站点可以同时满足两者，方案却把它们放入同一互斥槽。例如 Figma 可是 UI/UX，也可为设计工具；Pinterest Trends 既是灵感也可为研究工具；Canva 可为设计工具、模板素材和创作者平台。

若坚持每源一个二级，应先规定稳定的优先级，例如“用户来此的首要任务：浏览参考 > 获取可再利用资产 > 完成制作”。否则保留两个正交字段：`topic`（建筑/UI/品牌等）和 `mode`（灵感/素材/工具），不要把两者压成一个二级树。

### [P1] “室内与建筑”不应以 106/137 个源作为单一二级交付

106 是标签出现次数，不是一个同质集合；去重后的设计域总共才 137 个源。将建筑、室内、家具、家居、景观、材料合并为一个二级，会抹去用户现有的检索意图，且该组约占设计域 77%，成为无效的大桶。

建议至少保留可筛选的 `建筑与景观`、`室内与家居`、`家具与材料` 三个主题二级；若采用上条的双维模型，它们应是主题，素材/灵感/工具另作模式。只有在实际检索日志证明这些主题不可区分时才合并。

### [P1] “工具/开发”与“媒体/社区”的斜杠暴露出主分类规则尚未决策

斜杠不是单纯命名问题：它意味着两种不同的归属轴被并列。工具/开发混合“使用者完成任务的工具”和“开发者生产基础设施”；媒体/社区混合“内容生产/分发形态”和“参与方式”。例如 StackOverflow、GitHub、Vercel、n8n、Canva 都会在这两个轴上产生合理但不同的归类。

建议改为单一名词的一级（如 `开发工具`、`内容平台`），并把另一维降为 `source_type`/标签；若业务坚持合并，必须在规则中写出反事实测试：为什么 GitHub 属于该一级而 Reddit 不属，为什么 Canva 不同时拥有两个主一级。

### [P1] AI 二级规则不满足“AI 友好”，且与新词表不一致

保留现有 `guessAISecondary()` 会带入以下可复现缺口：

- 对 255 个 AI 源，函数有 **72 个（28.2%）返回空二级**；没有回退类，也没有“不确定待审”队列。
- 函数返回 `代码`，方案词表写的是“代码助手”；函数还会返回 `论文`，方案 AI 二级并未列“论文”。不改函数即无法保证受控词表闭合。
- 规则存在位置和子串误判：`Visual Studio Code` 被归为“语音”（`studio` 命中 `udio`）；`Agent` 的优先级也会覆盖同时具有视频/图像特征的产品。
- 方案把 Civitai 作为“设计素材”示例，而现有数据和 AI 规则都把它归为“AI/图像生成”；这是跨一级冲突，不是关键词补充能解决的。

应把“关键词猜测”降级为候选生成：规则输出置信度与理由，低置信度/冲突项进入人工审阅。验收样本应按二级分层抽样并报告 precision、未分类率和冲突率，而非只检查能否产出标签。

## 中风险问题与建议

### [P2] “每源三层标签”与现有多领域数据模型矛盾，需明确基数

现有 594 个源中有 38 个同时命中多个拟议一级组；例如 Product Hunt 同时是 AI、工具、产品，小红书同时是学习、社区、媒体。简报一处表述为“每源三层标签”，另一处仍延续 `domains` 多值数组，二者无法同时定义唯一主路径。

建议采用：`primary_domain`（恰一）、`secondary_domain`（恰一或 `未细分`）、`tags`（多值、承载交叉用途），并为旧 `domains` 保留只读别名。若决定多主一级，则放弃“MECE”与七项合计 594 的验收要求，改为清楚标示多重计数。

### [P2] 长尾不能按“1–2 个就合并”机械处理

动效当前只有 1 个原始标签，3D 素材、代码托管等也很小；但低数量可能意味着数据采集不足，不等于检索意图不存在。反例是招聘（4）、电子工厂（3）、IP管理（12），它们已有明确的业务用途，简报也主动保留。

建议以“独立检索意图 + 可预见增长 + 能否写出判别规则”决定保留；将无法稳定判别的长尾并入 `其他/待定` 并设复审阈值，而不要悄然塞入无关大桶。

### [P2] 跨一级例外没有完整映射，尤其是支付、物流、广告、创作工具

简报只裁决了电子工厂、网页设计、IP 管理、招聘；但现实数据还包括 PayPal/WorldFirst（现为 `工具/支付`，拟为电商“支付物流”）、Canva（现为 `媒体/创作工具`，拟为设计工具）、AdSense（现为媒体“广告平台”，拟为产品/商业“广告”）、以及中通快递目前被标成招聘网站。这些不是少数例外，而是新体系最容易造成不一致的边界簇。

应在实施前交付一张完整的旧域/旧二级到新主一级、新二级的映射表，并把无法从 URL+title 稳定推断的项列入人工裁决清单。

### [P2] 部分既有二级标签已经出现编码损坏；“保留旧二级数据”会把脏值带入新体系

抽查发现 `aistudio-google-com.md` 的 `domains` 中“图像生成”已是乱码字节，`code-visualstudio-com.md` 的“语音”同样如此；而其他源文件保存的是正常 UTF-8。同一语义因而会同时以正常标签、乱码旧标签和运行时新追加标签出现。

在新旧标签共存的方案中，这会直接破坏去重、父子关系推导和统计。迁移报告应先输出全部非受控词表/疑似乱码的领域值，决定是规范化时修复、还是纳入显式遗留别名；不能把“旧二级不改”理解为不校验。

## 建议的准入门槛

在任何代码改动前，补充以下工件并以现有 594 源跑通：

1. 受控词表、别名表、每个二级的“包含/排除/优先级”规则；禁止规则输出词表外值。
2. 一份逐源迁移报告：594 个唯一主一级、0 个未分类、0 个多主一级；二级未分类或冲突必须显式列出。
3. 至少覆盖上述边界簇和全部 7 个一级的回归样本；断言筛选、二级可见性、芯片计数、`/health` 与 `npm run check` 一致。
4. 迁移后统计同时显示唯一源数与标签出现次数，并在 UI 文案中区分两者。

完成这些门槛后，7 个一级的收敛值得继续推进；在此之前，直接重写 `autoAssignSecondaries()` 的风险高于收益。
