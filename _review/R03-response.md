## 对 P0 阻断项的回应

### P0-1: 缺少运行时迁移函数 → 接受，追加 `normalizeDomains()`

审查正确。改 `DOMAIN_ORDER` 数组不会自动迁移旧标签。需在 `scanSources()` 之后、渲染之前插入规范化步骤：

```
scanSources() → normalizeDomains() → autoAssignSecondaries() → 渲染
```

`normalizeDomains(domains, title, url)` 职责：
1. 旧一级 → 新一级映射（建筑→设计、室内设计→设计、开发→工具/开发 等）
2. 去重
3. 确保源恰有一个主一级（按优先级：AI > 设计 > 电商 > 工具/开发 > 媒体/社区 > 产品/商业 > 知识库）
4. 旧标签保留为 `legacy_domains`（只读，不参与筛选）

需在实施前写好并跑通 594 源全量测试。

### P0-2: 覆盖源数统计口径错误 → 接受，重新统计

旧数字是标签出现次数，不是唯一源数。正确的去重统计：

| 一级 | 旧标签来源 | 标签次数 | 唯一源数 |
|------|-----------|---------|---------|
| AI | AI | 255 | 待实测 |
| 设计 | 设计+建筑+室内设计+家居生活+景观 | 224 | ~137 |
| 电商 | 电商 | 68 | 待实测 |
| 工具/开发 | 工具+开发+前端 | 91 | ~89 |
| 媒体/社区 | 社区+媒体 | 58 | ~56 |
| 产品/商业 | 产品+IP管理+招聘网站+电子工厂 | 30 | 待实测 |
| 知识库 | 写作+学习+参考+搜索 | 19 | 待实测 |

验收标准改为：七项 `unique_primary_count` 之和 = 594，且每源恰有一个主一级。

### P0-3: check.js 遗漏 → 接受，纳入改动范围

`check.js` 的 `DOMAIN_ORDER` 也必须同步更新，且需要调用同一个 `normalizeDomains()` 函数。实施时把分类词表 + 别名映射收敛为一个可导入的常量模块 `domain-registry.js`，三处（server.js 渲染、server.js API、check.js）共用同一份。

## 对 P1 高风险设计问题的回应

### P1-1: 二级不是 MECE → 部分接受

审查发现了真实问题：设计灵感/素材/工具是按"用户用途"分，室内/UI/品牌是按"内容主题"分，两个轴混在一起。

**回应**: 不引入正交字段（过度设计），而是给二级分类加显式优先级规则。一个源命中多个二级时，按优先级取第一个：

```
设计二级优先级: 设计灵感 > 设计素材 > 设计工具 > UI/UX > 品牌与平面 > 室内与建筑 > 动效
```

理由：用户来设计网站，先看后拿再做。浏览意图优先于下载意图，下载优先于制作意图。主题类排在用途类之后——如果 Figma 同时是 UI/UX 和设计工具，UI/UX 胜出。

### P1-2: 室内与建筑不应 106 源塞一个二级 → 接受

拆分方案：

| 二级 | 覆盖 | 判别 |
|------|------|------|
| 建筑与景观 | 建筑设计、景观、城市规划 | archdaily/dezeen/谷德/建筑类 |
| 室内与家居 | 室内设计、家居生活、软装 | 室内设计/家居类 |
| 家具与材料 | 家具品牌、建材、材料商 | 家具/材料类 |

三个二级，各自可区分。不在实施前合并。

### P1-3: 斜杠命名 → 接受，改为单一名词

| 旧 | 新 |
|----|----|
| 工具/开发 | **开发工具** |
| 媒体/社区 | **内容平台** |
| 产品/商业 | **商业** |

理由：单一名词消除"两个轴并列"的歧义。`source_type` 字段已区分权威源/聚合源/平台/社区，二级分类不需要再承载这个维度。

### P1-4: AI 二级规则不满足"AI 友好" → 接受，纳入改造范围

审查给出的可复现数据（28.2% 未分类、`Visual Studio Code` → 语音误判、函数输出与方案词表不一致）说明 `guessAISecondary()` 不能"不改"。

修订方案：
- 不改 594 个源文件（承诺不变）
- 但 `guessAISecondary()` 需要修：对齐新词表、修子串误判、输出置信度理由
- 低置信度项不静默归类，标为 `AI/未细分` 等待人工审阅
- 与 `normalizeDomains()` 一起交付，一起测试

## 对 P2 中风险问题的回应

### P2-1: 多领域数据模型矛盾 → 接受

38 个跨组源需要明确规则。采用：
- `primary_domain` — 恰一（由 `normalizeDomains()` 按优先级确定）
- `secondary_domain` — 恰一（由 `autoAssignSecondaries()` 确定）
- `cross_tags` — 多值，承载交叉用途（从旧 `domains` 中跨组标签派生）
- 旧 `domains` 保留只读，不参与 UI 筛选

### P2-2: 长尾不能机械合并 → 接受

增加保留标准：独立检索意图 + 可预见增长 + 能否写出判别规则。三者缺一不可。满足任意两条即保留。无法判别的入 `其他/待定`，设复审阈值。

### P2-3: 跨一级映射不完整 → 接受，追加完整映射表

实施前交付一份 CSV/JSON 格式的完整映射表：每个旧（一级，二级）→ 新（primary, secondary, cross_tags）。无法从 URL+title 推断的项入人工裁决清单。

具体裁决：
- PayPal/WorldFirst → 电商/支付物流
- Canva → 设计/设计工具（不是媒体/创作工具）
- AdSense → 商业/广告
- 中通快递 → 电商/支付物流（当前误标为招聘，需修正源文件）
- Figma → 设计/UI/UX（优先级规则）
- Product Hunt → 商业/竞品研究
- 小红书 → 内容平台/社交平台

### P2-4: 编码损坏 → 接受，纳入迁移前清洗

迁移脚本先扫出全部非 UTF-8/乱码标签 → 规范化时修复或标为遗留别名 → 不把脏值带入新体系。
