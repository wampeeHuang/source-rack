三、分类维度（每个源必填 + 可选）

字段定义是否必填取值范围说明
name源名称✓ 必填自由文本如 "MDN Web Docs"
url域名/地址✓ 必填域名如 "developer.mozilla.org"
tier信任档位✓ 必填S / A / B / C / D / block决定搜索优先级和是否使用
domain所属领域✓ 必填设计/前端/AI/编程/工具/写作/产品/数据/全领域决定什么查询场景会用到它
type信息源类型✓ 必填权威源/聚合源/平台/社区/AI原生决定怎么搜它（site: 还是 API 还是 channel-search）
tags自由标签可选自由文本，逗号分隔辅助 grep 和精细匹配
notes备注可选自由文本降级理由、使用技巧、坑
✓ 6 个字段，必填 5 个。维度正交，不重复。

四、分类标准细则（固定在面板尾部展示）

档位标准

S领域标准。≤5/领域。月审。人工。
A高质量。≤20/领域。月审。3次差→降B。
B可用。不限。双周审。5次好→升A。
C试探。不限。周审。不主动搜。
D降级。不限。不搜。
block黑名单。不限。过滤。

类型 × 搜索策略

权威源site: 直接定位
聚合源站内搜 → 提取原始链接
平台@账号 或 channel-search
社区搜 + 标注置信度
AI原生API 调或结构化抓取

七、待闭环问题

#问题状态可能的答案
1"记录质量表现"怎么实现？○每源加 quality_score 字段，盘库时手动打分 / LLM 辅助评估 / 暂不自动化
2盘库频率？○每周轻量（C档） + 每月深度（全量 S-D）
3第一轮搜索结果"够了"的判定标准？○人工判断 / top-3 相关性阈值 / 暂不量化 > 全部看完手动决定
4领域匹配用标签交集还是 LLM？○先用标签交集（零成本），不够再上 LLM
5面板和 agentboard 集成还是独立？○集成到 agentboard 3099 /sources 路由
6存储格式：YAML 还是 JSON？○YAML（人类可读，和 tools/ 对齐）
7和 Chrome 书签的关系？○书签是一次性导入种子，之后独立维护。双向同步不做。
8分类标准谁来维护？○标准和规则在 Claude 端（CLAUDE.md），面板只展示不决策
